# Public benchmarks, five arms — October 2026

Run date: 2026-10-22, revision `309c2fd` (whole-document, classic and DCI arms), `3d62d4b` (first DocDB runs) and the review-loop revision described in [§ Review-loop changes](#review-loop-and-scorer-changes-2026-10-22), commit `1b990a8` (current DocDB rows). The same layer-by-layer protocol as the generated matters ([matters-2026-10.md](matters-2026-10.md)), applied to three public benchmarks through the eval harness: identical models (`claude-sonnet-5-5` root, `claude-haiku-5-5` sub-calls, review and judge), identical caps (24 root iterations, 600 s, $2 per query, $40 run ceiling), identical scorer (v3 strict scalar/text plus a model judge whose unresolved verdict is a miss), and a shared corpus cache so every arm reads the same ingested artifact.

**Judge protocol.** The runs were scored live with judge v1 (bare YES/NO at eight tokens). Reading the misses showed that judge rejecting correct numbers stated with their formula ("7.9%, computed as …" against `7.9%`), for every arm, and that a longer rubric alone made it snap to NO on long answers. All answers were therefore re-judged offline, without re-answering, under judge v3 (`rnsr.eval.rejudge`): the rubric states that method and source text are not a contradiction and that formatting is not substance, and the judge must explain in two sentences before a final-line verdict. Two passes were used for the first tables; the current DocDB rows use three (an odd number, so a majority always exists) and a deterministic presentation normaliser runs before the judge (`rnsr.eval.metrics.normalised_match`: `77.78%` against `77.78`, `0.0142` against `1.42%`, `$2.1 billion` against `$2,100`, rounding to the gold's stated precision and nothing looser). The tables below are the re-judged scores; live v1 scores are given where they differ materially. Per-pass counts are in each run's `rejudge_summary.json`.

> These figures supersede the July–September README results archived in [benchmark-history.md](benchmark-history.md), which were scored by text containment and first-number matching and are not comparable. Where it matters, the July *predictions* are rescored under today's scorer below so that a change in the ruler can be told apart from a change in the system.

## Arms

| Arm | Corpus presentation |
|---|---|
| Whole document in context | every document in the prompt, one call per question, cached prefix |
| Classic | ingested text as one string in the REPL |
| DCI | ingested text, one file per document, `ls`/`grep`/`read` in the REPL |
| DCI over raw files | fast text extraction of the original files: no layout model, no tables, no transcription |
| DocDB | typed tables, search ladder, annotations, certificates, claim review, trust tiers |

Whole-document, classic and DCI arms have no quotation verification, review or tiers. Spend is list-price provider usage summed over the questions; judge cost is excluded. Judge-scored is the number of correct verdicts decided by the model judge rather than exact match.

The two DocDB rows differ by one question, `00720`, the same answer in both runs ("gross margin is not a useful metric for American Express …") on which the three judge passes split 1–2 against the new wording and 3–0 for the old; the per-pass ranges overlap. On FinanceBench the review-loop changes moved nothing: the certificates here are `source_number` operands the controller chose, which the reviewer legitimately checks, so the certificate skip never fired; the nudge fired twice; the three-round cap produced two low-tier answers (both correct). Spend and sub-call counts are unchanged to within noise.

Reading. The four REPL/DocDB arms lie within 33–35 of 40, one standard error; whole-document prompting is five behind and its two judge passes disagree by five, so its position is the least certain. The questions still missed by every arm are gold-format mismatches rather than wrong answers: gold `$382.00` against "$381.6 million"; gold `77.78` for a question every arm read as asking for $700M; a Boeing effective tax rate whose gold carries the opposite sign convention to the filing's own table. Every 10-K fits a 1M-token window, so whole-document prompting could tie the REPL arms and costs ten times as much. DCI over raw files is at parity here, unlike on the heterogeneous dense matter, because 10-K PDFs have clean text layers and there are no scans to lose: ingestion's measured value is in unreadable pages, not in PDFs that already read. DocDB is the only arm with a parent-verified citation on every answer and a replayable derivation on 12 of 20 numeric questions, at three to four times the REPL arms' cost; the embedding gate held (0 batches) and no batch halted.

**Did DocDB get worse since July?** No, once the ruler is held still, and the detour is worth recording. July's own scorer reported 39/40 on these questions. Under judge v1 this week, July's *predictions* scored 29 and the current revision 24–25, which looked like a four-to-five question regression. The seven flipped questions all had the right number stated differently: July answered `0.01`, `7.9%`, `101.5%`, `1615.9`; the certificate path answered "ROA = 1.42% (net income … divided by …)", "7.9%, computed as the mean of …", once a raw 50-decimal quotient. Two things were wrong. The certificate path was carrying its proof in the answer text, which is a design error (the proof belongs in the certificate; the answer belongs in the form the question implies), fixed by bounding presented precision and asking for the number first. And the judge was penalising method text against terse golds, which the v3 protocol corrects. Under judge v3 on the same 40 questions: July's predictions **30/40**, this week's DocDB before the presentation fix **30/40**, after it **35/40**. The system is five questions better than July on the same questions and the same ruler, and the presentation fix accounts for all of it. The pre-fix run is preserved at `runs/public-arms/_prev-financebench-docdb-presentation/` and July's subset at `_july-financebench-docdb/`.

Misses by arm are in `runs/public-arms/financebench-report.md`; the pre-fix DocDB run is preserved at `runs/public-arms/_prev-financebench-docdb-presentation/` and the scope-only-reviewer run at `_prev-financebench-docdb-scopeonly/`.

## OOLONG, 50 questions (trec_coarse, 1k–65k tokens)

Flat synthetic text; 41 classify-then-count questions and 9 per-item questions. This is the classification-count path (`semantic_classify` with votes, parent `classification_aggregate`), not the certificate.

| Arm | Correct (judge v3) | Per-pass | Live v1 | Spend | Sub-calls | Latency p50 | Status |
|---|---|---|---|---|---|---|---|
| Whole document in context | 29 / 50 | 30, 32 | 33 | $0.99 | 0 | 5 s | 50 final |
| Classic | 39 / 50 | 39, 39 | 38 | $1.92 | 23,110 | 34 s | 50 final |
| DocDB, three votes per label (`3d62d4b`) | 34 / 50 | 34, 35, 34 | 33 | $16.77 | 6,915 | 42 s | 48 final, 2 budget_exhausted |
| DocDB, label once, certified count (current) | 36 / 50 | 36, 36, 36 | – | $2.90 | 895 | 22 s | 50 final |

| Task class | Whole document | Classic | DocDB `3d62d4b` | DocDB current |
|---|---|---|---|---|
| `counting` (41) | 22 | 31 | 27 | 28 |
| `user` (9) | 7 | 8 | 7 | 8 |

The first DocDB row labelled every item three times and then reviewed the count up to six rounds: 453 root calls, 6,915 sub-calls, 113 reviews, 11 halts, 13 low-tier answers, two queries out of budget. The current row labels once (`semantic_classify(votes=1)`, the rubric now says so), still certifies the count in the parent over the saved labels (all 50 finals carry a `classification_aggregate` proof), gives the reviewer one scope round on the vocabulary, and caps review at three rounds: 297 root calls, 895 sub-calls, 71 reviews, no halts, no low tiers, every query within budget. Accuracy is 36 against 34, within noise, and judge-stable across all three passes. Spend fell from $16.77 to $2.90, 5.8×, and is now 1.5× classic rather than 9×. Classic reaches 39 by having the controller call `llm_map` on every item, 23,110 sub-calls of a few hundred tokens each; it is cheaper per call but keeps no labels and no count certificate. The remaining gap of three questions is in `counting`, where the one-pass labels disagree with the gold rubric on borderline items; a second vote would buy those back at roughly three times the sub-call cost, which is the trade the previous row made for no gain. Whole-document prompting's long enumerations lose four under the explain-first judge, which reads to their final line rather than guessing from the counts. July's archived figures were DocDB 64% and classic 60%/58% under the loose scorer.

## What the public benchmarks add

They confirm the generated-matter decomposition rather than change it:

- Within a context window, the arms tie on accuracy on real documents too (FinanceBench, CUAD-long); whole-document prompting costs 10× the REPL arms on 10-Ks and about the same on contracts.
- Ingestion's value is in documents a model cannot otherwise read. Clean-text 10-Ks and contracts give it nothing to recover, and the raw-files arm is at parity; on the heterogeneous dense matter with 34 scans it was worth seven questions.
- DocDB's distinct output is still the receipt: a verified citation on every FinanceBench answer and a replayable derivation on 12 of 20 numeric questions, at 3–4× the cost. No other arm produces either.
- The classification-count path (OOLONG) was DocDB's weakest layer on cost. Labelling once and certifying the count over the saved labels keeps the receipt and removes the voting: $16.77 → $2.90 for the same accuracy, now 1.5× the cheapest REPL arm rather than 9×.
- The judge is part of the instrument and has to be engineered like one. A bare-token judge penalised every arm for stating a correct number with its formula and, given a longer rubric, snapped to NO on long answers; explain-then-verdict fixed both and moved every FinanceBench arm by five to twelve questions. Three passes with a deterministic normaliser in front leave two to five FinanceBench questions per arm on which the passes still split; on a twenty-verdict sample the judge agreed with a reader on 18, and both disagreements were gold-format or hedged-wording cases scored NO. Residual gold-format mismatches (`$382.00` for $381.6M, `$8.70` for $8,738M) remain, are shared by all arms, and are not repaired by the normaliser, which rounds only to the gold's own precision.
- An evidence layer must not carry its proof in the answer text. The certificate path did, cost DocDB five questions against its own July answers, and was corrected by bounding presented precision and leading with the number.

## Review-loop and scorer changes (2026-10-22)

Four changes were made after the first five-arm runs, each aimed at a measured cost rather than at a score, and the DocDB arms were rerun on FinanceBench and OOLONG with everything else held still.

| Change | Where | Intended effect | Measured |
|---|---|---|---|
| Certificate nudge: a final whose headline quantity appears in no verified quotation and carries no certificate is sent back once with instructions to bind it or quote the cell it came from (`require_certificate_for_derived`) | `harness/loop.py` | more replayable derivations | fired 2× on FinanceBench, 1× on OOLONG; replayable numerics 12 → 11 of 20 (noise); the controller answered the nudge by re-quoting, not by certifying |
| Review skip for parent-executed aggregate certificates; one scope round for certified classification counts (`claim_review_certificate_policy="skip"`) | `harness/claim_review.py` | fewer review rounds on certified fields | no aggregate certificates occur on these benchmarks (FinanceBench certificates are controller-chosen `source_number` operands); effect measured on the dense matters, not here |
| Review rounds capped at three (review, adjudication, one resubmission), down from six | `config.py` | bound root calls per contested field | OOLONG halts 11 → 0 with the labelling change; FinanceBench 2 halts, both answers correct, surfaced as low tier |
| Label once, certify the count (`semantic_classify(votes=1)` in the rubric) | `harness/prompts/base.py` | remove the vote multiplier | OOLONG sub-calls 6,915 → 895, spend $16.77 → $2.90, accuracy 34 → 36 |
| Presentation normaliser before the judge; three judge passes; adjudication sample (`rnsr.eval.rejudge --sample`) | `eval/metrics.py`, `eval/rejudge.py` | fewer verdicts left to the judge; visible variance | normaliser settles 1–3 FinanceBench answers per arm, all ones the judge had also accepted; judge-split rows 2–5 per arm; 18/20 agreement on the sample |

The honest summary is that one change paid (labelling once), one bounded a failure mode without changing a score (the round cap), and two did nothing measurable on these benchmarks because the conditions they address do not arise in them (the skip and the nudge). The adjudication sample at `runs/public-arms/adjudication_sample.jsonl` is unmarked for an independent reader; `adjudication_sample.assistant.jsonl` carries a non-independent pre-read.

## Reproduce

```bash
export RNSR_MAX_ROOT_ITERS=24 RNSR_MAX_WALL_S=600 RNSR_MAX_SPEND_USD=2 RNSR_RUN_SPEND_CEILING_USD=40
python -m rnsr.eval.migrate_cache --from runs/financebench/financebench-docdb/corpora --to runs/public-arms/corpora   # or let the harness re-ingest
for s in stuffing rlm-classic dci dci-raw docdb; do
  rnsr eval -b financebench -s $s --stratify 40 --seed 11 --run-dir runs/public-arms --corpus-cache runs/public-arms/corpora -c 3
done
python -m rnsr.eval.rejudge --passes 3 --questions-json runs/public-arms/questions-financebench.json --run-dir runs/public-arms/financebench-*
python -m rnsr.eval.public_arms_report --run-dir runs/public-arms --benchmark financebench --rejudged
python -m rnsr.eval.rejudge --no-rejudge --sample 20 --seed 11 --questions-json runs/public-arms/questions-financebench.json \
  --run-dir runs/public-arms/financebench-* --sample-out runs/public-arms/adjudication_sample.jsonl   # mark human_correct by hand, then --adjudicated FILE
for b in "cuad-long 10" "oolong 50"; do set -- $b
  for s in stuffing rlm-classic docdb; do rnsr eval -b $1 -s $s -n $2 --run-dir runs/public-arms --corpus-cache runs/public-arms/corpora-$1 -c 3; done
  python -m rnsr.eval.rejudge --passes 3 --questions-json runs/public-arms/questions-$1.json --run-dir runs/public-arms/$1-*
  python -m rnsr.eval.public_arms_report --run-dir runs/public-arms --benchmark $1 --systems stuffing,rlm-classic,docdb --rejudged
done
```
